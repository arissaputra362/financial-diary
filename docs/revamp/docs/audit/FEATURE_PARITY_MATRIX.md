## Explicit exclusions and parity safeguards

- Do not infer features from old mockups. Audit them against source and API.
- The product owner approved the Phase 2 mockup-aligned dedicated wallet screen; `/wallet` reuses existing wallet behavior and APIs. Do not add routes for reports, notification, or settings without product approval and source-backed need.
- The redesign owner’s instruction overrides the prior T-010 palette approval. It does not authorize changing money logic, data retention, privacy, API contracts, auth, household ACLs, or feature availability.
- Current acceptance gates are green for the revamp scope. Broad legacy Playwright failures remain documented as superseded test contracts and are not evidence of an unresolved Phase 3–5 product regression.
